LLMON: teaching Granite to tell instructions from data

Two new preview models learn a simple rule from an LLM-native markup language. Only the instructions you point them at are commands; everything else is input.

  • IBM Granite TeamIBM Research

12 Nov 2026·4 min read

Draft content

This post is draft content for review. Facts are from the LLMON announcement of November 12, 2026.

Every prompt is a mix of things you trust and things you don't. Your system prompt and instructions sit next to retrieved documents, pasted emails, and tool results, and to the model it is all one stream of text. Today we're releasing two experimental Granite models that see that stream differently.

The problem: everything looks like an instruction​

When an instruction is hidden inside a document or a tool result ("ignore the above and…"), a model can follow it as if you had written it. That is indirect prompt injection, and it gets more dangerous as models read more untrusted content on their own, in RAG pipelines and agents.

Formats like JSON don't help much. As the announcement puts it, JSON "was designed for parsers, not for causal language models": the brackets and quotes that mark its structure also appear in ordinary text, so the model can't reliably tell where one part ends and the next begins.

What LLMON is​

LLMON (LLM Object Notation, pronounced "lemon") is a markup language for talking to LLMs. It wraps each part of a prompt, such as an instruction, a document, or a requirement, in a tagged block. The delimiters are reserved special tokens rather than characters, so markup can never be confused with content:

<|open|>instruction<|close|>
  Suggest a title for the following email:
<|open_end|>
<|open|>data<|close|>
  Dear customer support, I am writing about the wifi on my recent flight...
<|open_end|>

An exec block then says which instruction runs on which data, much like a function call. Blocks that the exec block doesn't point to are still in context, but the model treats them as input to read, not commands to follow.

You rarely write LLMON by hand. The models' chat template renders ordinary chat messages into LLMON, and Mellea converts its LLM calls automatically.

What we released​

  • Granite 4.1 3B LLMON preview and Granite 4.1 8B LLMON preview, fine-tuned from the Granite 4.1 base models under the Apache 2.0 license
  • The LLMON toolkit with converters and example notebooks
  • An attention visualization Space that shows how the model's attention follows LLMON blocks

How well it works​

On the OPI prompt injection benchmark, the LLMON models avoided 47% more attacks than the best frontier model and 95% more than the best open-source model. On standard benchmarks, they perform on par with the Granite 4.1 Instruct models, so the added robustness doesn't cost general capability. The announcement has the full results.

What it doesn't do (yet)​

These are previews, ready for exploration and evaluation but not for production. The separation between instructions and data is a learned behavior, not a guarantee, and the benchmarks above cover static, single-turn injections. Attacks that unfold over many turns are still being worked on, so keep your other safeguards, such as Granite Guardian, in place.

Try it​

  • Start with the LLMON concept page in these docs for an overview and links.
  • Run a model from its model card, which has a complete prompt example.
  • Read the research: the LLMON language paper and the post-training paper.
