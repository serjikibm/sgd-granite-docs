# LLMON

:::caution[Preview]
LLMON and the Granite LLMON models are an experimental preview. They are ready for exploration and evaluation, but not for production use. The language, its special tokens, and the models may change in future releases.
:::

:::note[Draft content]
This page is draft content for review.
:::

**LLMON** (LLM Object Notation, pronounced "lemon") is a markup language designed for LLMs. It labels each part of a prompt, such as instructions, data, documents, and tool results, so the model knows exactly what each part is and which parts it should act on.

## Why LLMON

A typical prompt mixes trusted content, such as your system prompt and instructions, with untrusted content, such as retrieved documents, pasted text, and tool results. To the model, it's all just text. That causes two problems:

- **Prompt injection.** An instruction hidden in a document or tool result, such as "ignore the above and…", can be followed as if you wrote it. This is called indirect prompt injection.
- **Confusion about structure.** Plain text and JSON don't tell the model reliably where one part ends and the next begins. Smaller models in particular can mix up instructions, data, and requirements.

LLMON makes those boundaries explicit. The Granite LLMON models are trained on one rule: only the instructions and system prompt you point the model at are commands. Everything else, including documents, data, and tool results, is input to read, not instructions to follow. In IBM's evaluations, the LLMON models resisted substantially more prompt injection attacks than both frontier and open models, while keeping general capability on par with the Granite 4.1 instruct models. See the [announcement](https://huggingface.co/blog/ibm-granite/llmon-an-llm-native-markup-language-now-in-granite) for the results.

:::info[A trained behavior, not a guarantee]
The separation between instructions and data is learned during training. It reduces the risk of prompt injection, but doesn't eliminate it. The current models address static injections in a single turn. Attacks that unfold over many turns are still being worked on. Keep your other safeguards, such as [Granite Guardian](../trust/safety-and-security.mdx), in place.
:::

## How it works

LLMON wraps each part of a prompt in a tagged **block**, using reserved special tokens as delimiters so the markup can never be confused with the content. A simplified example:

```text
<|open|>instruction<|close|>
  Suggest a title for the following email:
<|open_end|>
<|open|>data<|close|>
  Dear customer support, I am writing about the wifi on my recent flight...
<|open_end|>
```

Each block gets an ID, and an **exec** block then states which instruction to run, which inputs it operates on, and where the output goes, much like a function call. Content that the exec block doesn't point to is present but ignored.

You don't need to write LLMON by hand:

- **Chat messages:** the model's chat template renders ordinary messages into LLMON. You mark which instructions and data the model should act on, and the template does the rest.
- **Mellea:** if you build with [Mellea](https://mellea.ai), it converts its LLM calls to LLMON automatically.
- **Structured data:** the converters in the [LLMON repository](https://github.com/generative-computing/llmon/tree/main/llmon/lang) turn JSON and other structured input into typed, individually addressable blocks.
- **Your own concepts:** you can fine-tune an LLMON model with a LoRA adapter to understand domain-specific tags. See [Adapters and composition](./adapters-and-composition.mdx) for background, and the [fine-tuning examples](https://github.com/generative-computing/llmon/tree/main/llmon/examples/lora-finetuning) in the repository.

## Models

| Model | Fine-tuned from |
| ----- | --------------- |
| [Granite 4.1 3B LLMON preview](https://huggingface.co/ibm-granite/granite-4.1-3b-llmon-preview) | Granite 4.1 3B Base |
| [Granite 4.1 8B LLMON preview](https://huggingface.co/ibm-granite/granite-4.1-8b-llmon-preview) | Granite 4.1 8B Base |

Both models were released on November 12, 2026, under the Apache 2.0 license, and are part of the [Granite Experiments collection](https://huggingface.co/collections/ibm-granite/granite-experiments-6724f4c225cd6baf693dbb7a). They don't use a conventional chat template, so use the template that ships with the model. Other Granite models aren't trained on LLMON.
